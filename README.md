# ラピッドプロトタイピング課題 ― テーマ「信じる」

## 課題

- テーマ「信じる」から、アプリを企画・設計して**プロトタイプまで**作る
- 作りこむことよりも、アイデアを形にして確かめることが目的

## テーマの解釈

「信じる」は、結果がわからないものに賭けること。
**成立しなかった時に失うものがあるから、「信じる」は重くなる。**

## 作ったもの：信じてMe! ― 約束の担保

> 約束に、質（しち）を入れる。守れば担保は燃え、破れば封が開く。

1. 友だちと約束をするとき、「恥ずかしい一言」を担保として預ける
   - 担保を出す人は約束の中身で選ぶ：**自分だけ**（例：明日は遅刻しない）／**相手だけ**（例：内定が出たら焼肉おごって）／**2人とも**（例：週末に水族館へ行こう）
2. 封をすると、担保は書いた本人にも相手にも読めなくなる
3. 期限がきたら（期限前でも可）、約束した人と相手が**それぞれ申告**する。担保を出した人ごとに「守った／破った」を答える（相手の答えは結果が出るまで見えない）
4. 結果は**担保を出した人ごと**に決まる
   - その人について2人とも「守った」 → その人の担保は燃えて、誰にも読まれずに消える
   - その人について2人とも「破った」 → 封が開いて、その人の担保が相手に公開される
   - 答えが食い違った → 「不一致」。その人の担保は封をしたまま永久に読めなくなる
   - 例：「2人とも」の約束で片方だけ破った → 破った人の担保だけが公開される
5. 自分の担保が燃えた（守った）割合が「信頼残高」として残る（不一致は別に数える）
6. 2台で使うときは、同じWi-FiにあるPCの中継サーバーで同期する。1台で手渡しして使うこともできる

## 技術

Kotlin Multiplatform ＋ Compose Multiplatform（Android / iOS 共通）。2台の同期は Ktor の中継サーバー
